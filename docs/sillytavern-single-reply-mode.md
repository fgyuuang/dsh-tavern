# 原版酒馆 · 单次回复

这是适用于每一份作者预设的回复方式，与“DSH 原版 / 梦境思客DSH”Agent 预设独立。

在“本局设置 → 预设 → 回复方式（本局）”选择“原版酒馆 · 单次回复”；新游戏的开局页也有同名选择。切换要求当前生成、变量处理和脚本任务空闲，从下一回合采用。

切换保留当前作者预设的本局副本、提示原文、功能选项、宏覆盖、正则、助手脚本数据、人物卡、世界书、变量与历史。源副本转为本局独立配置，后续资源库更新不会覆盖它；需要采用新版时重新选择源预设。切回 DSH Agent 后继续使用对应 Agent 流程。已保存草稿仍保留，暂停任务的继续标识会清理。

## 一轮如何执行

1. 根据原 `prompt_order`、启用状态、角色及深度，展开作者提示、人物卡、世界书、历史、宏、EJS 和助手注入。
2. 清除这次请求的 DSH 工具和额外 Agent 指令。主生成只请求一次完整回复，沿用普通正文流式显示；平行事件、选项等由源预设在同一回复中输出。
3. 最终回复只提交一次 Timeline。原正则和 HTML/iframe 负责展示；官方 MVU 使用同次回复的原 `UpdateVariable` 命令进行本地事务处理，其他脚本收到相应消息事件。

此模式不会自动发起 Agent 草稿检查、修订、状态规划、记忆整理、人物设计、候选、后续模块或压缩模型任务。所有这些 Agent 配置仍保留。网络重试复用本步骤编译结果，不重复执行输入宏；once 注入成功提交后才消费。预设脚本如明确调用额外生成，仍按原脚本开关执行，因此“单次”指主生成流程，不能解释为任意扩展都禁止调用模型。

本局 RPC 为 `getGenerationMode` 和 `setGenerationMode({sessionId,generationMode})`，值为 `agent` 或 `sillytavern-once`。`playPresetId` 和旧的 `requestMode` 无需替换，已有历史仍在原列表中。

## 兼容边界

已修复旧兼容编译器的 marker 角色覆盖、绝对深度排序、强制 strict_tools 改写和简化世界书匹配。当前仍复用 DSH 的兼容层，不能宣称所有酒馆扩展行为与 SillyTavern 逐字节相同。

当前模型适配器能采用源 temperature、maxTokens 和可映射的 reasoningEffort；top_p 等未支持参数保存在源副本和诊断中。世界书概率及 sticky/cooldown/delay 时效、独立玩家 persona 数据源、部分 Author's Note / outlet 以及第三方数据库插件仍有差异，详见[编译器依据与边界](design/sillytavern-single-reply-compiler.md)。新流程已做本地与浏览器夹具验证，实际模型输出体验和复杂角色卡脚本仍需在安装后确认。
