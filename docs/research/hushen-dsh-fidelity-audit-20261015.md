# 狐神抚 DSH（hushen-dsh）复刻保真度审计

审计对象：新增的第二个原生 Agent 预设 `hushen-dsh`。
来源基线：`D:\pro\SillyTavern Launcher GUI\other\[主预设] V19.7.3 狐神抚 · 毓忻.json`
（6,454,579 bytes，SHA-256 `f5d65d9d…a87f51`）。

方法：用插件自身的 `inspectPreset` / `previewPresetConversion` / `compileHushenContract` /
`resolveHushenPresetMacros` 对源文件做纯本地编译，逐条比对**源启用条目**与**实际送入模型的规则文本**，
并用 sha256 校验保留条目的逐字一致性。不执行源助手脚本、不发模型请求。

## 结论

**原作者规则层的复刻是扎实且可验证的**：默认启用的 29 条非空原文全部承接，其中 20 条逐字保留，
12 个被 `setvar` 包裹的作者正文值 12/12 完整并入最终规则文本，没有任何一处被改写成新编的短提示词。

**高级助手模块层是"显式未迁移"**，而不是被静默砍掉：能力清单按项标注 partial/unsupported，
披露诚实。这不是复刻缺陷，而是范围边界。

## 三、真实差距（需如实告知）

1. **原助手整包（约 4.85 MB 玄狐脚本）不执行**，只做静态注册表解析。其 20 个注册模块
   （狐构 / 狐忆 / 狐搜 / 狐映 / 狐裁 / 平行世界 / 狐刻 / 手机 / 桌宠等）为 manifest-only、
   `enabled:false`。这些功能在源预设中由脚本运行时提供，DSH 里**不运行**。
2. **hushen 没有任何测试文件**。dream-sike 有 10+ 个测试；hushen 为 0。工程缺口。
3. **狐稿默认是关闭的**。源文件里 `🦊狐稿~`（分段 1633 字 / 全量 2882 字）、留言 439、
   狐构 1313、狐映 2181、总结 582、狐忆 1662 全部 `disabled`。而 DSH 对**每回合**强制
   唯一草稿 → 六维审阅 → 补丁修订。所以"六维 review"是本适配层自有的协议（复用 dream-sike 的轴），
   **不是作者狐稿的复刻**；`adaptDraft` 在默认配置下是死代码。
4. **作者的分节标题被丢弃**。25 条"启用但空"的条目（`----📝文风要求(选一)----` 之类）未进入契约，
   模型看不到原预设的分节结构提示。轻微。
5. **交付口径不一致**：契约统计 29 条 entries，但 `readHushenAgentRules` 分页只返回 **3 条**
   （内容全在，约 9,590 字）。属报告粒度问题，非内容丢失，但会让"作者规则共 29 条"的说法对不上。
6. **作者变量原文只进后台结算**（`writingAgentSettlementRules`），正文写作 Agent 拿不到。
   这是有意设计（防双 MVU），但若结算路径未真正命中，MVU 规则等于丢失，需实卡验证。
7. 文档 `docs/hushen-dsh-agent.md` 写"尚未安装到运行版"，实际已部署；文档过期。

## 四、建议

- 补 hushen 的契约/设置/审阅测试，至少覆盖：来源识别、29 条编译、20 条逐字保留、
  12 个 setvar 并入、能力清单状态、六轴审阅门控。
- 在 `readHushenAgentRules` 里保留作者分节标题，或在契约中单列"激活选项清单"，便于模型理解结构。
- 统一"作者规则条目数"的口径（契约 entries vs 分页 rules）。
- 实卡验收重点：后台结算是否真的吃到 `writingAgentSettlementRules`；狐策正则与美化链在 Agent 模式下
  的最终呈现；狐构/狐映折叠投影的显示效果。
