## 四、思维链是否真的送达

**是，但路径需要说明。** 思维链的送达链路是：

```
默认思维链条目 {{setvar::sleep_var_thought_of_chain::…}}   ← 存变量
        ↓ 宏解析
写作模式条目 …根据上述写规完成草稿…＋{{getvar::sleep_var_thought_of_chain}}   ← 读变量
```

关键证据：模型在自己推演中引用了「**根据上述写规完成草稿**」。
该字符串经全仓检索，**只存在于 `dream-sike-contract.js` 的 `adapt()`**（安装版同源，命中数 1）。
该条文之后紧跟 `{{getvar::sleep_var_thought_of_chain}}`，直接测试确认展开为 4,264 字符、
含思维链全部四章与「必须需要严格遵守"<meta>"协议进行思考」的 meta 绑定。

因此：**写作模式确实进入请求 → 紧随其后的思维链同样进入请求。**

注意：DSH 会把每个步骤的预设投影消息以临时方式注入，**不落盘到会话日志**，
所以直接在会话里搜不到思维链原文。这正是需要用「模型引用的独有字符串」来反证的原因。

## 九、与先前酒馆的对比

先前酒馆是**单请求巨量上下文**：全部提示词 + 历史 + 素材一次送入，模型一轮直出正文。
DSH 的 Agent Harness 拆成了：

- **front → system 常驻**：persona（破限）+ 框架（已核实进入 system 消息）
- **back → 每步注入**：文风、思维链、写作模式、场景/平行协议（已核实随写作模式送达）
- **工具链**：读取规则 → 准备 → 草稿 → 审稿 → 修订 → 确认
- **后台**：变量结算 + 记忆维护

**等效性判断**：作者定义的写作要求（文风 / 思维链四章 / 叙事者 / 字数 / 禁词 / 输出协议）
与破限声明**都进入了模型请求**，且产出合规。差异在于多了一层「草稿→审稿→修订」，
这是先前酒馆没有的——属于**增强**而非减损（turn 4 的两次 patch 就是这层带来的实际修正）。

## 十、未决与建议

1. **本评估基于会话日志的间接反证**：DSH 不落盘预设投影消息，因此思维链的送达是
   通过「模型引用了只存在于 adapt() 的独有字符串」反推的。若要做到直接可验证，
   建议在诊断中增加「本步实际注入的 back 投影摘要」记录。
2. 会话中另有 2 处长度 11,822 / 13,462 字符的文本含 dream_plot，经核对为**请求上下文转储**
   而非提交正文；真实正文以 `sike_put_draft` 参数为准（上表）。
3. 该局为**单卡单局、共 4 回合**的样本。文风是否达到玩家先前认可的质感，
   仍建议由你直接阅读正文判断——本报告只能证明规则与协议层面已复刻到位。

## 边界

本报告核对的「达到先前酒馆效果」限于**规则注入、协议合规、流程执行**三项可观察事实。
不构成对文学质量的判定，也不能推断提供商策略层面的变化。
