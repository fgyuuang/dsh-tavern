# 作者模块分阶段与上下文优化

本次维护基线 `487b4f6e`，分支 `codex/dream-sike-dsh-agent`。在既有 Agent 草稿、时间线与后台任务边界内分阶段接入，不重写角色卡或原预设。

## 执行阶段

| 阶段 | 作者模块 | Agent 执行 |
| --- | --- | --- |
| 写前查询 | 角色分析、信息差、记忆、世界书、变量与历史 | 按本局档位使用 1–2 次模型查询请求，按需检索，不为重复覆盖资料追加请求 |
| 正文与审阅 | 已选文风、视角、输入处理、字数、场景、八股超杀/自检修复 | 一次 `sike_put_draft` 同时提交唯一正文和六维审阅；宿主同次检查，通过后直接提交 |
| 局部修订 | 审阅指出的具体缺陷 | 按本局档位使用 0–2 次修订请求；每次以一组 `patches` 和更新后的审阅批量修改 |
| 状态结算 | 最终正文、变量、状态与记忆 | 正式正文提交后由后台一次组合工具提交，草稿阶段不写入状态；模型请求次数单独统计 |
| 后续展示 | 平行事件、旧说书、大调查、行动选项、小摘要 | 状态结算后由一次聚合任务与工具提交生成已启用模块，独立显示在正文之外 |

只有启用的作者模块才执行。旧说书和小摘要原默认禁用，更新不会自动开启。大总结和聊天模式仍是独立回复模式，第三方数据库材料仍标明接入限制。已确认的历史正文不改写，新回合采用新流程。

平行事件仍按作者规则呈现场外人物与同时发生的行动，但在 Agent 流程中是结算后的派生展示，不合入正文，不回写本轮变量、记忆或权威世界事实。场内人物不会因此自动知情。共创建议不代表已经发生；小摘要只记录本轮既成事实。需要改变正式状态的事件留到后续主线确认。

初稿同时包含六维审阅，宿主在同一次流程中做协议检查并提交，不再串行调用独立准备、审稿、check 和 ready 工具。修订额度可在本局档位中设置为 0、1 或 2；每次修订把多个唯一定位的局部片段合并提交，全部成功才保存新版本。额度用尽但仍有阻断问题时保留草稿并报告，不无限重试。后台仍每局一个持久 Agent；变量结算和后续展示按各自阶段授权，附加模块不能改写已结算状态。

玩家直接继续下一回合时，可选后续互动生成让出后台，不拖延新一回合正文生成；已提交正文与变量不受影响。生成未完成会标记停止，不在重启后偷偷重发。

## 上下文管理与本轮改动

稳定前缀保存人物卡、常驻世界书和长期偏好；选定前置作者规则通过原生 system 装配。每轮追加行动、动态世界书、变量反馈及记忆目录，按需检索原历史和文档。当前工具循环保持调用/结果配对，正式剧情由独立时间线保存。原生压缩保留近期原文及摘要，工作目录可在压缩后重读。

`sike_read_turn` 增加分项读取：首次仍返回完整当前材料；连续规则续页可设置 `includeMaterials=false`、`includeDraft=false`，仅请求草稿时可 `includeRules=false`。显式完整补读随时可用，压缩或重启后须重新核对原文。选择省略只改变本次工具返回，不删除作者规则、材料或历史，不伪称这些引用已经被模型重新读取。

对同一真实存档的内存副本做只读规则分页回放：两次续页完整返回共 53,497 字符，分项返回共 22,581 字符，减少 57.8%。规则正文一致、用户存档写入为零。此结果度量工具载荷字符，不能换算为实际 token、账单或缓存命中率改善。

后台附加模块只接收当前职责的作者规则；未启用模块不装配到本局任务。正文前查询与正文修订/恢复请求数由本局档位控制；状态结算限制一次组合提交，附加展示限一次模型请求。结算模型请求暂无限额，人物设计等维护过程可能增加请求。目标是减少无效重试及串行审稿；实际耗时、调用量和缓存效果仍须通过新回合的运行记录对照，不能由阶段设计推定。

工作台新增“上下文缓存”：读取标准化真实 usage、按任务及模型分组；显式前缀检查只返回哈希与字符证据。旧记录缺少 usage 显示未知，不以字符数推算实际命中率。窗口占用、输入处理量与提供方缓存命中是三个不同指标。

真实旧会话样本中，前台 39 次有效用量合计缓存读取率 81.38%，后台 13 次为 87.98%；最新前台 6 次调用仍累计 949,679 输入 token。3 次规则续页重复携带 33,031 字符非规则内容。详细口径、模型切换影响与限制见 [缓存审计](context-cache-audit-20261011.md)。这些是改造前样本，不是本次上线后的节省结果。

## 保留的后续优化方向

- 完成回合后进一步缩减工作轨迹在请求视图中的占用，保留正式剧情、原始事件、工具配对和分支恢复；当前未直接删除提供方所需的 reasoning replay。
- 将后台变量 schema 与规则进一步按版本共享，状态变化仍明确提供。本次不假设已有后台历史包含完整最新状态。
- 小摘要原来的十层深度替换策略不能自动作用于拆分面板。本次采用 DSH 压缩及长期记忆，不将摘要面板伪装成原生压缩。
- 按模型实际窗口、路线及质量对照评估压缩时机；本次没有擅自减少近期保留轮数或改变压缩阈值。
