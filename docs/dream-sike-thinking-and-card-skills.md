# 梦境思客：写前流程与人物卡 Skills

## 检查结论

本轮基线是 `dcecba081606ea451b2fe957c79067c2a8ab5efc`，维护分支为 `codex/dream-sike-dsh-agent`。

原梦鲸预设的已启用写规仍由本局快照装配，角色分析、叙事者、文风、篇幅、场景栏和平行事件都属于写作要求。默认写前决策流程要求核对设定、人物认知、写规，以及内部考察至少三条候选事件链。已存在的 `sike_check_draft` 六维审稿会阻止无审阅或存在 revise 的草稿确认；局部修改后必须重审。

缺口是写前流程仅靠指令：基线没有写前准备工具，`sike_put_draft` 不验证已读取本轮材料。此前独立验证局压缩后的真实轨迹是 put → check → patch → check → ready → read，读取出现在写作完成之后，不能证明按要求先核对材料。三个已有救赎之理局的历史草稿也没有准备记录，其中一个最近草稿只有 put/check/ready 三次调用，且三局的历史草稿均没有当前六维审稿结果。这些是旧回合记录，不将它们冒充本轮新代码的实测。

完整私有推理无法由工具轨迹验证。本次保持内部剧情推演要求，检查可观察的资料读取、执行约束、审稿结果与最终正文；不保存完整思考链，也不以简报结构通过声称文风和剧情已经还原。

## 本轮实现

原预设已启用默认写前决策流程时，执行顺序为：

1. `sike_read_turn`：持久记录当前回合材料已由工具返回，提示世界书、变量预览是否截断。
2. 按需检索历史、世界书、当前变量和分支记忆。
3. `sike_prepare_turn`：保存 scene、characters、knowledge、style、progression、stopAt 六项简短事实或执行约束。
4. put → check → 必要 patch/recheck → ready → 宿主一次正式提交 → 后台结算。

记录绑定会话、回合、操作、分支、剧情修订号及写规契约摘要。缺读、缺准备、过期分支、过期写规不能起草或确认；修改准备使现有审稿失效。相同准备的重试保持幂等；失败恢复将准备与原草稿一同重绑到唯一续处理回合。未启用该源写前条目时保留既有流程。

正文工作窗增加“写作准备”和“六维审稿”折叠区，后者注明是 Agent 判断。准备与草稿均不写正式消息，不调用变量结算；关闭工作窗只影响展示。

契约版本由 2 升至 3，压缩/重启后重新装配。旧已提交回合不补造准备或审稿；旧未完成草稿继续处理时须依当前规则读取、补准备并重审。

## 仍需区分的事项

- 开局前端按钮、iframe 生命周期、图片放大和输入桥由宿主执行，Skill 化的是选择方法、诊断与维护流程。
- 原卡开局脚本仅开启世界书条目，重新选择可能留下旧集合；本轮未修改其共用世界书或旧存档。
- 原有 literal dotted key 与嵌套变量不是同一种结构，不能通过重新初始化整局修正旧历史。本轮 Skills 明确路径和状态归属，但不批量迁移旧数据。
- 原预设未开启的脚本与思考条目不因新模式自动开启。
- 结构校验与 Agent 审稿不能证明三条内部候选实际构思了多少，也不能证明救赎之理全部角色、检定和文风体验等价；这需要代表性剧情正文与真实前端行为验收。
