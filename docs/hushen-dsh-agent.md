# 狐神抚DSH

独立原生 Agent 预设 ID 为 `hushen-dsh`，来源是本机“[主预设] V19.7.3 狐神抚 · 毓忻.json”。作者提示词通过本局源副本编译，写法仍取自启用的作者原文；新增的原生 persona 和 Skills 负责工具流程，不另造文风。

## 使用

在包含本功能的维护版本中，通过预设库导入原 JSON，再在新局或空闲旧局的“Agent 预设”选择“狐神抚DSH”。本局设置提供原作者分组、互斥选择、关闭项、快捷开关、自定义原文、正则与接入状态。更换来源会先核对作者标识，不匹配时保留当前配置。

回复方式仍可独立切换为“原版酒馆 · 单次回复”。切换保留本局预设设置、变量和历史。该兼容模式允许原助手启动，但 DSH 缺少原助手部分宿主 API，不能据此认为玄狐整包功能已经运行。当前局和新游戏默认值不会被准备工具自动切换。

## 原文如何进入 Agent

| 原预设职责 | 当前实现 |
| --- | --- |
| 初始化宏、选项宏、第一阶段基础要求、第二阶段输出前检查 | 按原选中顺序展开；作者宏命名空间每轮独立清理，避免旧开关残留 |
| 多角色感知边界、导演、自然、自定义等写前方法 | 完整原文参与当前规则；内部核对，用原生资料工具补全依据 |
| 文风、人称、转述、抢话授权、篇幅与正文标签 | 使用原文及本局选项；不增加梦境思客标签 |
| 狐稿 | 保留作者检查标准，转为唯一草稿、六维可观察审阅和按预算批量局部修订 |
| 狐策、短评、留言、时间地点、总结 | 启用时随本次完整草稿输出；狐策沿用原正则交互，复杂实卡尚待验收 |
| 狐构与狐映需求 | 保留原文协议；停用旧控制器后以本地折叠文本展示大纲和载体，避免隐藏正则导致空白；不生成额外素材 |
| MVU 模式 | 原变量规则保存为状态阶段原文，前台不输出补丁，后台使用已有聚合提交、MVU 与 Timeline 协调器 |
| 记忆、历史与压缩恢复 | 使用当前分支原生记忆文档和检索；不把导出时的旧狐忆文本视作新局事实 |

默认写前查询 1 次，首次正文 1 次，必要修订最多 1 次；本局可将查询设为 1–2 次、修订设为 0–2 次。模型请求尝试受共享入口计数，失败与重试会计入。正文后的状态任务沿用现有恢复机制，没有新增一个“狐裁”控制器反复生成。已选狐策等目前随正文完成，并未迁往另一次后续调用。

作者思考链保留决策职责与顺序，旧思考/草稿输出封装改为原生工具协议。公开的是简短执行约束、检查依据和修改记录，不能保证模型内部推理逐字采用作者的文本模板。

## 原助手接入边界

原 JSON 有 220 个 prompts、215 条排序记录、40 条正则及 2 个启用助手。默认启用 62 个排序项，其中 29 个非空；正则 18 条启用、22 条禁用。助手主程序约 485 万字符，包含自己的多模型与数据系统。

本次只解析其静态注册表，不执行整包程序。原作者 21 组下拉设置，以及快捷、杀八股、普通/严格条目和自定义编辑被映射到本局设置。重复的 SPreset 正则备份不作为第二套规则执行。原禁用设置保持禁用。

设置页的“原助手能力接入”明确列出：

- 原作者规则、原文设置、原生草稿、修订、资料检索与后台结算已接入。
- 狐忆使用 DSH 分支文档；旧 IndexedDB、向量缓存及表格数据库尚未导入。原导出不含这些数据库。
- 狐裁的原文规划与审阅可用；其原两阶段模型策略、指纹缓存、独立重试和降级尚未迁移。
- 平行世界独立推进、骰子、图谱、狐刻自动触发、手机、桌宠和高级素材/前端控制器尚未迁移。
- 原总结压楼、狐搜筛选链和小说模式等高级管理策略仍需专门适配，不能因原文槽存在就宣称可用。

源文件中的旧搜索、偏好、总结、狐忆和大纲等临时资料默认隔离。用户显式修改本局动态槽后，记录本局来源标识，才允许重新注入。源 JSON 和资源库原件不被重写。
