# 正文优先的写作 Agent 与 Desktop 界面

## 本次问题

旧实现按模型请求次数推进阶段。读取写作 Skill 占用初稿请求后，真正出稿进入 `draft-retry`，被归为修订；草稿保存后的检查与确认也消耗同一额度。预算耗尽即在模型分发前抛错，使已有正文无法完成提交。结束钩子的旧恢复指令还要求再次读取、准备、检查与确认，增加了循环。

## 执行契约

- 当前回合的首要成果是完整正文。角色卡、世界书与原预设继续由现有上下文装配；只为缺失的具体事实调用查询工具。
- 原作者提示词、配置开关和注入顺序沿用现有资源。Skills 说明执行方法，不重写作者的文风规则。
- 加载 Skill 或读材料后仍无正文时，可以继续起草。查询与额外修订额度控制可选优化，不拒绝正文生成、确定性格式修复或最终确认。
- 模型可以直接输出正文，由宿主保存、检查并交给既有提交事务；也可以调用正文工具。正文工具默认沿用保存后收束行为，`finalize: false` 明确保留草稿以继续优化。
- 写作准备、六维审阅与流程回执作为建议。私有协议、正文格式结构、版本、分支、操作身份和最终正文一致性仍须通过检查。
- 使用 `completion` 单独记录完成正文所需请求。台账继续记录全部实际模型请求；它不代表供应商的计费额度。
- 正式正文通过现有 Timeline 事务提交一次，后台随后处理变量、附加内容。中途预览不会启动脚本或结算。

主聊天通过 DSH 原生 `conversation.chat.turnTail` 展示当前回合的正文预览，读取普通文本增量、正文工具顶层 `text` 增量或已保存草稿。它只显示可见正文，过滤私有思考与其他参数；正式回合关闭后移除，由正式渲染结果接替。

## 界面参考与边界

参考仓库为 `https://github.com/dataelement/dsh-desktop`，参考提交 `87df2859444d4f62ff3ac2de89a633719c788cc3`。采用其单列侧栏、紧凑模式控件、原生主题和低层级菜单的布局方式。

- “游玩 / 卡片 / Agent”在同一行；Agent 与游玩使用同样的品牌头。
- 项目 Agent 的工作区只管理项目目录和对话列表；四种原生模式放在聊天输入框旁，仅空白会话可切换，首条消息后显示锁定模式。
- 创作工作台用紧凑标题与横向标签页，保留模块管理、键盘导航和每局显示偏好。
- 原作者设置保留全部分类、选项、来源和高级设置；分类与菜单使用 DSH 的主题变量。
- 使用真实的 `label-*`、`brand-primary`、`specific-menu` 和 elevation token，移除工作台中的无效主题变量与绿色回退配色。

这次改动不升级底层 DSH 运行时。独立项目 Agent 使用原生标准、PTC、极简、创造四模式；两个写作预设继续由各自插件提供，并使用宿主的共享存档与提交引擎。

## 验证方式

核心回归覆盖零修订、Skill 后继续出稿、同一步读取与保存、直接正文、可选审阅降级及协议保护。真实本地 DSH Harness 使用脚本适配器验证工具配对与单次提交，不调用外部模型。

界面验证使用 Edge 隔离页面与实际源码组件，覆盖浅色/深色、桌面/390px、键盘与模块切换。隔离截图使用示例数据，不能替代玩家实际角色卡的剧情质量验收。真实模型验收只允许 Agnes。
