# 模型推理强度的来源与边界

原生模型选择与导入预设是两个参数来源。原版酒馆单次回复会在 `llm/stream` 阶段合并预设的采样参数，其中可能含 `reasoning_effort`。因此只在 `agent/request` 中校验，不能防止预设后续再次注入不兼容值。

- `agent/request`：校验会话选择中残留的强度。
- 最终流式请求：完成兼容预设、导入与模板投影后，按准确 provider/model 元数据再检查一次；不支持时省略参数，使用模型默认。
- 兼容投影：原生已选择的强度优先于预设中的采样强度；保留预设原文件及其他采样、提示词与正则。
- 归一化请求沿用同一 attempt 标识，在计数、日志和供应商调用之前重新分发，不重复计费台账。

## 界面

输入框公开 slot `conversation.input.right` 增加强度控件。它与原生 `modelSelection` projection 同步，使用本局模型设置接口保存。供应商未声明强度档位时显示“模型默认 · 未提供档位”；这不等同于上游模型没有推理能力，不能凭模型名称强行声明 low/medium/high。

## 离线检查

通过生产兼容策略和生产流式 hook 检查无强度、low、medium、high 预设与有无模型能力、原生选择 high 的16种组合。每种只到达模拟供应商边界一次，保留模型路由、作者消息和其他采样参数。隔离浏览器验证强度可见、保存、模型路由保持，以及无档位提示。没有发送真实模型请求。
