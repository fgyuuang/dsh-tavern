# 酒馆直接回复：中断正文保留与续写

## 诊断与修复范围

2026-10-15 检查到一次直接回复在同一模型步骤内产生两个替代版本，历时约 28 分钟。最新尝试已收到 4,556 个可见文本字符，最终因流空闲 300 秒失败。正文仍在原生 `assistant/attempt.stream` 中，现有重放入口却会重新执行原输入。

本次为已授权的功能修复，覆盖单次回复的失败恢复边界：原生流 → 中断归档 → 明确续写 → Timeline 单次提交。新增两个领域模块，接入现有编排、错误重试、提交与对话显示；不更换模型、供应商或预设提示词，不改动已提交楼层。

范围预算重新按该恢复边界设为 20 个文件、700 行（包含生成客户端、文档和专项测试）。原有 `tests/request-frame-coordinates.test.mjs` 工作区差异不归入本次提交。上线使用部署脚本的版本比对、文件备份和回滚脚本。

## 行为

- 插件不再设置 8 分钟总生成时限。收到正文后若连续 90 秒没有新增正文，仍会中断并保留内容；上游 pi-ai 的 300 秒流空闲超时是另一层限制，不由此改动移除。
- 已产生可见文本或发生 TIMEOUT 时不自动从头重试。无正文的其他瞬时错误仍保留原有一次重试。
- 文本从原生持久日志恢复，忽略 reasoning 和工具块；重试版本分别归档。展示时移除明确标记的私有推理块，以纯文本展示未完成 HTML。
- 中断归档保存在本局 `interruptedReplyArchive`，显示在对话内，最新未完成版本默认展开。生成中、重启后和续写完成后仍保留；完成后默认折叠。
- “接着补完”核验失败尾部、正文摘要、预设契约和剧情分支，将原始玩家输入再次排入原生 Agent，并在原预设编译结果之后附带已保存正文与补完要求。正文作为续写前缀，提交位置校验失败时明确报错，不会静默回退从头生成；续写不会再次触发原输入的 `MESSAGE_SENT`，也会移除已包含在正文前缀中的重复 assistant prefill。
- 完成时合并保留正文与新增部分，经原有 Timeline 提交一次，之后才执行脚本事件和变量结算。完全重复的长前缀或至少 32 字符的精确边界重叠可去重；不做模糊正文改写。
- 再次超时会保留整段已有前缀与最新补充；没有新文本仍保留前缀。排队失败恢复旧标记；重启发生在排队前后时，仅恢复尚未开始的同一失败尾部。
- “重新生成本轮”保留从头生成语义；已有中断归档仍可查看。

## 验证与限制

专项测试覆盖原生压缩文本块、替代版本、隐私块、连续超时、过期契约、分支和提交校验、排队失败、重启恢复、等待限时、单次提交和变量延后结算。浏览器验证正文常驻、默认展开、纯文本安全渲染、续写摘要、防重复点击及窄屏。

这些测试使用本地模拟流，不发起模型请求。供应商仍可能续写重复或改变文风，精确去重无法纠正所有语义重复。进程在原生流持久化之前被强制终止，尚未写入日志的最后一段无法从日志恢复。
