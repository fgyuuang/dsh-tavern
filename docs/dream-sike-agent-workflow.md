# 梦境思客：原生 Agent 工作流

## 入口与结构

原生预设有两个独立身份：`tavern` 显示为 **DSH 原版**，保留原生对话、后台结算、手动候选项、重新生成和回退交互；`dream-sike-dsh` 为 **梦境思客DSH**，拥有专属创作操作栏、创作设置侧栏和正文工作窗。梦境的候选生成放在可展开的“行动灵感”中，继续复用已验证的候选工具；它不自动替玩家行动。

新梦境游戏从导入的 `梦鲸思客V4-0915.json` 读取作者规则，按文件名和原提示词标识核对来源，不跟随原版当前选择的其他提示词文件。缺少或无法唯一确认来源时明确报错。原版继续使用原来的来源选择和预热流程；新游戏默认值不因安装改变。

两个身份切换时分别保存完整规则快照、变量选项、正则及 Skill 开关。第一次切入尚未配置的身份使用该身份的初始来源；已有配置则原样恢复。已隔离的配置不被资源库自动刷新覆盖，需要明确选择来源才重新载入。前后台空闲及存储版本检查仍是切换门槛，人物卡、世界书和历史属于同一游戏。原生 DSH 已开始会话的预设锁定规则仍通过现有插件入口兼容；这里不会新建或替换历史会话。

配置归档只在切换或完整读取时加载；轻量状态和后台结算不会读入其他预设的全文。不同设置页同步已保存改动；存在未保存修改时提供重新载入入口，保留当前编辑内容。

### 手机浏览器交互

1023px以下使用单行创作工具入口，默认收起；展开为两列按钮，工具区独立滚动且最多占可视区32%。输入正文自动收起工具，极短视口隐藏辅助栏，保留原生输入器、草稿、停止/发送生命周期。手机的“更多”菜单在工具区内展开，不再以固定定位盖住输入区；桌面和原版菜单保留原定位。

新版侧栏的关闭与新增标签入口适配当前 `data-dsh-pane` 合约。作者原文抽屉随可视区高度和偏移调整，键盘弹出时关闭按钮仍在可视范围。

检查覆盖320、390、430px及844px横屏，模拟400、280、220px键盘可用高度，实际命中测试确认发送按钮未被覆盖，并验证点击时草稿内容完整。移动布局、交互、Agent工具和作者设置合计22项检查通过；采用当前宿主样式和DOM合约的浏览器夹具，不能代替Android/iOS真机键盘验收。截图在 `output/playwright/mobile/agent-idle-390.png`、`agent-tools-390.png` 和 `agent-typing-390.png`。

本局设置里的“梦境思客 DSH Agent 预设”按任务阶段组织能力。文风和人物表演要求仍来自选定作者原文；Skills 说明读取、草稿、检查和恢复的工具操作，不另写一种默认文风。

| 阶段 | 配置与职责 |
| --- | --- |
| 角色与场景 | 玩家角色、人称、输入处理、人物分析 |
| 叙事与文风 | 主文风、附加文风、叙事者、字数 |
| 写前决策 | 原作者思考强度、决策方法及自定义增量 |
| 正文与附加输出 | 写作/聊天/总结、场景、平行事件、选项、剧情共创 |
| 审稿与状态结算 | 自检、逐段检查、MVU要求及后台提交边界 |
| 模型与材料接入 | 原模型适配、数据库及表格材料接口的兼容状态 |

指定原 JSON 的13组、72项、2个变量均映射一次。71个提示词选项可选择，原宿主专用设置仍显示实际限制。单选用下拉，多选用开关；来源抽屉保留原选项与逐字提示词。全部高级规则与正则仍可访问。搜索跨阶段，窄屏导航折行；兼容说明和变量帮助按需展开。

## 作者方法与 Agent 执行

```mermaid
flowchart LR
    A[玩家当前行动] --> B[原文规则与分支资料]
    B --> C[作者决策步骤]
    C --> D[唯一草稿]
    D --> E[检查与局部修订]
    E --> F[确认并提交一次]
    F --> G[后台变量与记忆结算]
```

六个原生工具保持原名称，继续使用持久前台与后台 Agent、Story Timeline、原生压缩和分支记忆。旧局启用相同能力，新游戏可使用原生 `dream-sike-dsh` 预设。开关保存仍只影响本局，前后台空闲后原子应用，从下一回合生效。

1. **读取。** `sike_read_turn` 返回当前运行任务的玩家行动、分支资料与作者规则完整索引。相关历史优先使用真实消息 ID/原 uid；`uid_<floor>` 明确只是当前分支真实楼层别名。
2. **原法。** 默认、V4pro、自定义三种写前流程均接入准备门槛。作者的设定检索、历史定位、格式清单、人物认知、输入解释、写规与叙事者步骤保留。思考输出前缀、闭合标签等旧传输要求调整为原生工具边界；不保存或展示模型私有推理。
3. **按需补读。** 规则页提供原 ID、原文/解析哈希及双续读位置；大条目分片后可完整重组。空的宏赋值结果不占读取项数，原条目与宏效果仍在索引和来源中保留。选定写作模式的完整展开内容可以直接按索引读取。
4. **准备。** 六项简短执行约束与本回合、分支和规则版本绑定。可选 `coverage` 只接受实际提供的材料/规则引用；读范围保留引用与哈希，不复制规则全文，不伪称已检查内部思维过程。
5. **写作。** `<dreamer_input>` 保留作者原输入区域名称，并绑定当前运行回合。玩家引用的宏按字面材料处理，不能重写预设变量。转述、禁止抢话、深度扮演和大纲采用各自作者控制范围；明确授权的深度扮演限当前回合，下一回合仍交回玩家。
6. **检查与结算。** 作者自检与逐段修正保留检查规则，执行转为草稿局部修改。变量格式不会被混进正文；MVU对应要求映射到提交后现有后台结算。聊天和总结采用自己的作者步骤与格式豁免，原生系统角色同步选定模式。

默认仍最多12个模型步骤、两次草稿修订。工具消息保持配对，过程留在过程面板，最终正文只提交一次。失败保留本回合资料与草稿，压缩后可以再次读取原规则和记忆文档。

## 原文与兼容边界

原 JSON、人物卡、世界书和旧历史没有被重写。原始启用状态、顺序、UUID与哈希可以核对。模型专用前缀和虚构工具身份不作为原生 Agent 权限；源码原文在来源抽屉及审计包留存。第三方数据库宏材料、Kimi Partial等尚未完成的扩展效果仍有兼容说明，不把一个可选开关当作扩展成功运行的证明。
