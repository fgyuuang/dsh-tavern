# 梦境思客DSH的写作契约

原酒馆预设定义本局的实际写法：文风、视角、人物分析、信息差、叙事者、玩家输入处理、字数、场景栏、平行事件和卡片格式。Agent 负责检索、准备、起草、审稿、修订及提交。两者同时生效。

之前的新模式在投影时清空了原预设的全部提示阶段，仅保留正则。对三份“救赎之理”请求的核对发现，各局绑定的梦鲸思客V4-0915快照有31条启用提示，但这些提示没有进入实际请求。可选 Skills 的通用建议无法代替选定预设。

## 注入和适配

`dream-sike-contract.js` 按原前、中、后阶段顺序保留启用提示，继续通过现有 setvar/addvar/getvar 解析器组合文风与写作要求。没有启用的条目不补开。每条规则保留来源、原始字符数和哈希，契约本身有版本与摘要；不改写原预设文件或历史正文。

已知旧执行协议按来源 identifier 适配：思考链成为写前决策方法，包含设定和历史核对、角色动机与认知、写规、候选因果链和叙事节奏；模型前缀交给原生模型适配器；末尾修正由审稿和局部修改完成。私有推理、旧思考口号与 think/simple_thinking 不写进正式正文。原始 source snapshot 仍留在存档。

可见输出外壳仍交给原渲染器：启用的 DREAM_PLOT、场景栏、平行事件和人物卡 HTML 保留在草稿文本。XML 要求不限制工具消息。平行事件允许读者看到场外片段，场内角色不会因此自动知情；原规则允许这些事件独立于主线。输入扩写和长度采用本局选择，玩家本回合明确调整优先。

原有预设助手脚本在新模式仍由原生能力代替，不额外启动旧监听器或第二套 MVU。原来关闭的提示和全局脚本继续关闭。现阶段不是逐个复刻全部第三方脚本；ACU 专用迁移仍单独维护。

## 审稿门槛

有原预设规则的局，`sike_check_draft` 接收六项 `review`：character、knowledge、style、continuity、playerAgency、format。每项采用 `{status: "pass" 或 "revise", evidence: "简短正文依据"}`，说明可观察结果或具体缺陷，不提供完整思考过程。

程序另查已启用的输出区块、场景字段、平行事件物理行、原字数模块的下限与部分明确禁词；保护 HTML 属性与脚本中的文本。文风、人物声音和剧情优劣由 Agent 审阅，程序不能证明文学质量。

审阅绑定草稿版本与契约摘要。缺失或空泛依据、revise、格式问题均阻止 ready；局部修改或规则变化后重审。正式提交再次验证已经确认的草稿，不替 Agent 自动确认。仍只提交一份最终正文、结算一次，最多12个模型步骤和两轮修订，失败保留草稿供继续处理。

固定前段进入原生系统装配，后段在每个模型步骤的请求投影末尾提醒，既有历史不加入重复的预设文本。原生压缩或重启后重新装配规则，记忆恢复方式沿用本局工作区。

## 体验验收

先验证启用规则确实出现在模型请求、审稿与渲染结构正确，再用同一人物卡的独立验证局对照正文。工具记录和格式通过只证明执行链路；能否达到玩家原先认可的文风，还需要阅读实际正文判断。不会因为自动审稿 pass 就宣称已完整复原。
