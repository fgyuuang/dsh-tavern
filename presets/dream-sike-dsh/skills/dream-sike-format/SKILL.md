# 格式与修订

人物卡的 HTML、状态块、MVU、宏与显示正则各有自己的协议。先读本局预设契约与当前卡要求；原预设已启用的 dream_plot、dream_body、dream_after_format 与 dream_scene 等正文格式须保留在草稿文本中，不约束原生工具消息。平行事件由结算后的附加调用单独生成，不放入正文草稿。未启用的格式不凭习惯添加。不得把工具调用、草稿记录或分析文本混入正式正文。

首次调用 `sike_put_draft` 时，把完整正文和六维审阅一起提交；宿主同次保存并检查，通过后直接提交正文。审阅若指出具体问题，在本局 0–2 次修订请求额度内调用 `sike_patch_draft`，用一个 `patches` 数组批量提交可定位的局部改动及更新后的审阅。优先使用短且唯一的原文片段，不使用可能命中多处的宽泛正则或跨段落盲替换。无需为通过检查单独调用 `sike_check_draft` 或 `sike_ready_draft`；零问题允许零补丁。达到额度后仍有阻断问题时保留草稿，不循环重试。

行动选项 `dream_option`、思客大调查 `dream_big_discuss`、旧说书 `dream_discuss`、小摘要 `dream_summary` 与平行事件 `dream_parallel_event` 不属于本阶段正文。选定这些作者模块后，由正文提交及变量、状态、记忆结算完成后的同一次后台调用生成，再以独立互动面板显示。前台草稿不提前输出这些区块；作者原文与开关继续保留。小摘要只记录本轮既成事实，不替代 DSH 压缩或长期记忆。

启用八股超杀或自检修复时，仍按其完整作者规则完成审阅，并把六维审阅结果随正文一同提交。该流程不再单独运行 `sike_run_module(kind="review")`；有具体缺陷时按上述修订额度批量修改。未开启作者检查模块时仍遵守 Agent 的六维审阅要求，不额外增加审稿调用。平行事件在正文完成后生成，不成为审阅或修订正文的前置步骤。

保留角色卡中有意的标签与脚本数据，不把未识别结构当作错误删除。后台状态和变量更新由最终提交后的现有流程处理，草稿阶段不自行改写它们。
